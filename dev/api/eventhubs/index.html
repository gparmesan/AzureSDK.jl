Event Hubs API

AzureSDK.EventHubs — Module
AzureSDK.EventHubs

Azure Event Hubs client modelled on Python's azure.eventhub: EventHubProducerClient, EventHubConsumerClient, EventData, EventDataBatch, checkpoint stores and load balancing. Transports: AMQP over TLS, AMQP over WebSockets, and HTTP (REST, sending only).

AzureSDK.EventHubs.BlobCheckpointStore — Type
BlobCheckpointStore(blob_account_url, container_name; credential=nothing, kwargs...)
BlobCheckpointStore(container_client::ContainerClient)
from_connection_string(BlobCheckpointStore, conn_str, container_name; kwargs...)

A CheckpointStore backed by an Azure Storage blob container (which must exist). credential accepts everything a Blob ContainerClient accepts: a TokenCredential (Entra ID; needs the Storage Blob Data Contributor role), an AzureNamedKeyCredential or account key, an AzureSasCredential or SAS string, or nothing when blob_account_url carries a SAS. Other keyword arguments (e.g. retry_total, api_version, connection_verify) are passed to the ContainerClient.

Blob layout (shared with the other Azure SDKs): <namespace>/<eventhub>/<consumer group>/ownership/<partition> and .../checkpoint/<partition>, with the data in blob metadata.

AzureSDK.EventHubs.CheckpointStore — Type
CheckpointStore

Abstract type for stores that persist partition ownership and checkpoints so several consumers can share the work and resume where they left off. Subtypes implement (all dictionaries use the Python SDK's key names):

  • list_ownership(store, fully_qualified_namespace, eventhub_name, consumer_group) -> Vector{Dict{String,Any}}
  • claim_ownership(store, ownerships::Vector{Dict{String,Any}}) -> Vector{Dict{String,Any}}
  • update_checkpoint(store, checkpoint::Dict{String,Any})
  • list_checkpoints(store, fully_qualified_namespace, eventhub_name, consumer_group) -> Vector{Dict{String,Any}}

Ownership keys: fully_qualified_namespace, eventhub_name, consumer_group, partition_id, owner_id, last_modified_time (Unix seconds), etag. Checkpoint keys: fully_qualified_namespace, eventhub_name, consumer_group, partition_id, offset, sequence_number.

AzureSDK.EventHubs.EventData — Type
EventData(body=nothing; properties=nothing, content_type=nothing, correlation_id=nothing, message_id=nothing)

An event to send to, or received from, an event hub. body may be a String or a byte vector.

Fields: body (bytes; for received events with an AMQP value/sequence body, the decoded value), properties (application properties, Dict{String,Any}), content_type, correlation_id, message_id, raw_amqp_message.

Received events also expose (as properties) sequence_number, offset, enqueued_time, partition_key and system_properties.

AzureSDK.EventHubs.EventHubConsumerClient — Type
EventHubConsumerClient(fully_qualified_namespace, eventhub_name, consumer_group, credential; kwargs...)
EventHubConsumerClient(f::Function, args...; kwargs...)   # do-block

Receives events from an event hub (azure.eventhub.EventHubConsumerClient).

Keyword arguments (in addition to the transport/retry options of EventHubProducerClient):

  • checkpoint_store: a CheckpointStore to persist checkpoints and balance partitions across several consumers.
  • load_balancing_interval (30 s), partition_ownership_expiration_interval (6 × load_balancing_interval), load_balancing_strategy (LoadBalancingStrategy.GREEDY or BALANCED, default GREEDY).
  • prefetch (300): events buffered per partition.

Only TransportType.Amqp and TransportType.AmqpOverWebsocket can receive.

AzureSDK.EventHubs.EventHubProducerClient — Type
EventHubProducerClient(fully_qualified_namespace, eventhub_name, credential; kwargs...)
EventHubProducerClient(f::Function, args...; kwargs...)   # do-block: closes the client afterwards

Publishes events to an event hub (azure.eventhub.EventHubProducerClient).

credential is a TokenCredential (e.g. DefaultAzureCredential()), an AzureNamedKeyCredential or an AzureSasCredential.

Keyword arguments:

  • transport_type: TransportType.Amqp (default), TransportType.AmqpOverWebsocket or TransportType.Http (REST; sending only)
  • http_proxy: proxy for WebSockets / HTTP, e.g. (proxy_hostname="proxy", proxy_port=3128)
  • custom_endpoint_address, connection_verify (CA bundle path)
  • retry_total (3), retry_backoff_factor (0.8), retry_backoff_max (120), retry_mode
  • auth_timeout (60 s), user_agent

See also from_connection_string.

AzureSDK.EventHubs.receive — Method
receive(consumer, on_event; partition_id=nothing, starting_position=nothing,
        starting_position_inclusive=false, owner_level=nothing, max_wait_time=nothing,
        track_last_enqueued_event_properties=false, on_error=nothing,
        on_partition_initialize=nothing, on_partition_close=nothing)

Receive events and call on_event(partition_context, event) for each. Blocks until the consumer is closed (e.g. with close(consumer) from another task or from inside a callback).

  • partition_id: receive from one partition only; otherwise from all partitions (balanced with other consumers when a checkpoint store is set).
  • starting_position: where to start when there is no checkpoint: "-1" (beginning), "@latest" (default), an offset string, a sequence number, a DateTime (UTC), or a Dict mapping partition ids to positions.
  • max_wait_time: if no event arrives within this many seconds, on_event(context, nothing) is called.
  • owner_level: exclusive (epoch) receiver priority.
  • on_error(context, error), on_partition_initialize(context), on_partition_close(context, reason::CloseReason.T).

Callbacks for different partitions may run concurrently on different threads.
